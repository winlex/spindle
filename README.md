# Spindle

Трекер задач с асинхронной обработкой. REST API, PostgreSQL, фоновые воркеры с повторами,
graceful shutdown, структурированные логи, метрики, health checks, Docker Compose и CI.

> **Статус: в разработке.** Проект является обучением языка Go и находится на этапе 1 из 48 уроков.
> Из заявленной функциональности пока реализован только каркас: бинарник `api`, утилита
> `migrate` и пакет метаданных сборки `buildinfo`. Ниже описан **текущий** состав, а не конечный.

---

## Что это

Spindle — backend-сервис для управления задачами внутри проектов: проекты, задачи, комментарии,
история переходов, роли участников. Изменение состояния задачи порождает фоновые задания,
которые обрабатываются воркерами: сервис кладёт задание в очередь на PostgreSQL, воркеры забирают
его с lease, обрабатывают с повторами и уходят в dead-letter после исчерпания попыток.

Очередь хранится в той же базе, что и доменные данные, — это сознательный выбор: отдельный
брокер не нужен, пока объём не вырастет, а транзакция «записать задачу и положить задание»
остаётся атомарной.

## Как запустить

Требуется Go 1.27 или новее. Внешних зависимостей пока нет — только стандартная библиотека,
поэтому `go mod download` ничего не качает.

```bash
git clone <url-репозитория>
cd spindle

make build      # собрать бинарники в bin/
make test       # прогнать тесты
make check      # форматирование + vet + тесты, всё одной командой
```

Запуск:

```bash
./bin/api        # печатает версию процесса и время старта
./bin/migrate    # заглушка, выводит "not implemented"
```

Одиночные команды, если `make` не подходит:

```bash
go run ./cmd/api
go test ./...
go test -race ./...                    # требует cgo: на macOS нужен xcode-select --install
go test ./... -coverprofile=coverage.out && go tool cover -func=coverage.out
```

## Что внутри

```
spindle/
├── cmd/
│   ├── api/main.go            # точка входа: конфиг, сборка зависимостей, запуск, сигналы
│   └── migrate/main.go        # утилита миграций
├── internal/
│   └── buildinfo/             # метаданные сборки: версия, версия Go, время старта
├── Makefile
├── go.mod
└── .gitignore
```

Правила раскладки, принятые в проекте:

- **`cmd/<имя>/main.go`** — только связывание. Бизнес-логики в `main` нет: она плохо покрывается
  тестами, и `os.Exit` в ней завершает тестовый процесс целиком.
- **`internal/`** — весь прикладной код. Директория закрыта от импорта извне на уровне
  компилятора, это гарантия, а не соглашение.
- **Пакеты по функциональности** (`auth`, `tasks`, `projects`), а не по слоям
  (`controllers`, `services`, `repositories`).

## Команды проекта

| Команда | Что делает |
|---|---|
| `make help` | список целей |
| `make build` | собрать все бинарники в `bin/` |
| `make run` | запустить сервис |
| `make test` | тесты |
| `make race` | тесты с детектором гонок |
| `make cover` | покрытие и разбор по функциям |
| `make fmt` | отформатировать код |
| `make fmt-check` | проверить форматирование, ничего не пишет |
| `make vet` | статический анализ |
| `make check` | `fmt-check` + `vet` + `test` |
| `make tidy` | привести `go.mod` в порядок |
| `make clean` | убрать `bin/` и `coverage.out` |

## Метаданные сборки

Пакет `buildinfo` печатает версию, версию компилятора и время старта процесса:

```
$ ./bin/api
spindle-api dev (go go1.27.1, started 2026-10-01T10:24:11Z)
```

Версия подставляется линкером при сборке релиза и по умолчанию равна `dev`:

```bash
go build -ldflags "-X github.com/<user>/spindle/internal/buildinfo.version=v0.1.0" -o bin/spindle-api ./cmd/api
```

Тег git при этом подставляет версию в `debug.ReadBuildInfo()`, но **не** в нашу переменную:
внедрить значение в код своего модуля можно только через `-X`. В образе без каталога `.git`
блок `vcs.*` от `debug.ReadBuildInfo()` будет пустым — отсюда и нужен `-X`.
