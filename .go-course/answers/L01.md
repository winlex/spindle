## 1. Ответы на контрольные вопросы

> Пиши своими словами, это не экзамен. «Не понял» — полезнее «не знаю».

**В1.** Что означает директива `go 1.27.1` в `go.mod` и чем отличается от `go env GOVERSION`?
Почему это разделено на два понятия? Что произойдёт, если поставить `go 1.30.0`?

>В go.mod версия сборки проекта, а в переменной окружения - версия утилиты самой для сборк

**В2.** Почему код из `internal/buildinfo` нельзя импортировать из другого модуля?
Чем это отличается от соглашения «не импортировать utils»?

>Код из нее виден только внутри дерева. Это механизм, а не соглашение

**В3.** Что конкретно проверяет `go vet ./...` и почему этого недостаточно для качественного кода?

>Проверяет формат printf, copylocks и недостежимый код. Этого недостаточно, потому что логика кода не проверяется сама

**В4.** Почему в `main` мы вызываем `os.Exit(1)`, а не `panic(err)`? Что изменится при `log.Fatal`?

>Мы даем возможность "клиенту" самим определять значимость ошибки. Если сделаем fatal, то приложение отдаст ответ с кодом 1 и дальше непойдет выполнять

**В5.** `main` вызывает `fmt.Println`. Это нормально или нарушение правила «main только связывает»?
Где граница?

>Я считаю, это нормально, ибо это базовая функция. Если мы делаем логику, которая подразумевает доплонительного изучения и поддержки, то нужно выносить в отдельный модуль.

**В6.** Чем `go run ./cmd/api` отличается от `go build -o bin/spindle-api ./cmd/api` + запуск бинарника?

>run запустить сервер и приложение само, а build сначала сделает бинарники, а их потом сможем отдельно запустить

**В7.** Пакет с 30 функциями, «нужными всем» — почему в Go это признак архитектурной ошибки?

>В Go нельзя импортировать utils не по вкусу, а потому что компилятор запрещает циклы. Если в общем пакете появляется функция, которой нужен доменный тип, общий пакет начинает зависеть от домена — и дальше домен не может использовать ничего из него. Второе: метод можно объявить только на типе из своего пакета, поэтому удобную функцию над Task приходится звать как utils.FormatTask(t), и общий пакет неизбежно попадает в зависимости домена. Третье: у пакета из 30 функций нет предмета — его нельзя описать одним предложением и нельзя заменить целиком. То есть снаружи это похоже на модульность, но внутри контракта нет.

**В8.** `-race` требует cgo, обычная сборка — нет. Последствия для CI на macOS и для Docker
со `CGO_ENABLED=0`? Почему это ограничение окружения, а не языка?

>Внутри -race используется cgo, а там в свою очередь - gcc. Если мы выключем cgo, то при сборке просто не сможем вызвать cgo

**`internal/buildinfo/buildinfo.go`**

```go
package buildinfo

import (
	"fmt"
	"runtime"
	"time"
)

var version = "dev"

type Info struct {
	Name      string
	Version   string
	GoVersion string
	StartedAt time.Time
}

func New() Info {
	return Info{
		Name:      "spindle-api",
		Version:   version,
		GoVersion: runtime.Version(),
		StartedAt: time.Now().UTC(),
	}
}

func (i Info) String() string {
	return fmt.Sprintf("%s %s (go %s, started %s)",
		i.Name, i.Version, i.GoVersion, i.StartedAt.Format(time.RFC3339))
}
```

**`internal/buildinfo/buildinfo_test.go`**

```go
package buildinfo_test

import (
	"strings"
	"testing"
	"time"

	"github.com/winlex/spindle/internal/buildinfo"
)

func TestNew(t *testing.T) {
	info := buildinfo.New()

	if info.GoVersion == "" {
		t.Error("GoVersion is empty")
	}
	if info.StartedAt.IsZero() {
		t.Error("StartedAt is zero - New must always fill the time")
	}
	if !strings.HasPrefix(info.GoVersion, "go1.") {
		t.Errorf("unexpected GoVersion: %q", info.GoVersion)
	}
}

func TestInfoString(t *testing.T) {
	ts := time.Date(2026, 9, 28, 12, 0, 0, 0, time.UTC)

	tests := []struct {
		name string
		info buildinfo.Info
		want []string
	}{
		{name: "dev build", info: buildinfo.New(), want: []string{"spindle-api", "go1."}},
		{
			name: "all fields set",
			info: buildinfo.Info{Name: "api", Version: "v1.2.3", GoVersion: "go1.27.1", StartedAt: ts},
			want: []string{"api v1.2.3", "go1.27.1", "2026-09-28T12:00:00Z"},
		},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			got := tt.info.String()
			for _, want := range tt.want {
				if !strings.Contains(got, want) {
					t.Errorf("String() = %q, want it to contain %q", got, want)
				}
			}
		})
	}
}
```
